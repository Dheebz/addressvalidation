# Project review — 5 October 2026

## Local product state

- August 2026 national G-NAF is active and May 2026 is retained for rollback. Both releases have compact street and locality alias maps. The live August API resolved `9 ABBOTT CL PALMERSTON ACT 2913` to `GAACT714904529` as an alias.
- Two API replicas sit behind HAProxy. Two PostgreSQL nodes use Patroni and an etcd quorum for automatic database takeover. All containers still share one local host.
- ID, suggest, match, validate, format, and bulk endpoints return structured address components and release context. The admin portal exposes release and service status.

## Review items 1–4

1. **Overload:** Each API replica now admits at most 16 concurrent address requests by default, with no queue. Extra requests receive HTTP 429 `API_BUSY` and `Retry-After: 1`. A separate container using persistent connections completed 32,000 scheduled requests at 1,600 requests/s in 20 seconds: 29,347 HTTP 200, 2,653 deliberate HTTP 429, zero transport timeouts. This is local admission behaviour, not a production capacity guarantee. See [SATURATION-REHEARSAL.md](SATURATION-REHEARSAL.md).
2. **Bulk retention:** The original seven-day worker cleanup was verified with an aged local job. It now defaults to 24 hours and reads a shared database setting controlled from the admin portal. Queued jobs past the period and stale running jobs are failed and removed; active work can finish. The API reports the current period and expiry times. See [API.md](API.md).
   The public page shows only the current upload and result, with no job history in browser storage. Status and result endpoints require the job's secret token; production also binds access to the submitting identity. Existing jobs from before this change cannot be reopened and expire under the retention policy.
3. **Match quality:** Real street/locality aliases are loaded from G-NAF into release-specific compact maps. Both retained national releases were backfilled from their official archives. Alias expansion requires a unique canonical target, avoiding broad locality aliases such as `BELCONNEN`. The national regression corpus has 18 positive and 11 negative cases, including a real street alias and wrong-house alias input. It is still derived from G-NAF; the 0.8 score threshold needs independently labelled real user inputs before it is a production quality claim. See [QUALITY.md](QUALITY.md).
4. **Recovery:** An isolated rehearsal makes a compressed PostgreSQL logical backup, restores it into a second database, compares the active release and row count, reads a restored address, kills primary A, observes B promote, restarts A as standby, and checks API recovery. During a 90-second continuous probe, 699 of 900 reads succeeded and 201 returned structured, retryable HTTP 503 responses. The longest success gap was 20.21 seconds; the final 15 seconds were clean. A hard primary failure therefore still causes a real interruption on this local configuration. A separate full national logical backup and disposable restore also passed: both release states, 15,949,543 active addresses, alias counts, and a sample G-NAF ID matched. Restore timing and independent-host disaster recovery remain to be proven. See [OPERATIONS.md](OPERATIONS.md).

## Item 5: admin access and observability

The local admin portal now requires an antiforgery token for release-changing forms, keeps a PostgreSQL-backed history of operator actions, and exposes admin liveness and database readiness checks. Non-Development mode requires OIDC sign-in with the `Address.Admin` role and persistent Data Protection keys before startup. Compose remains localhost-only and runs in Development without sign-in. The history includes preparation requests and background outcomes, promotions, rollbacks, timestamps, actors, and request IDs; structured `AdminAudit` logs report persistence failures. The implementation has rendering tests and a local HTTP smoke check. An actual identity provider, shared key storage, HTTPS ingress, centralized telemetry, and production access review still need validation before an Azure deployment. See [OPERATIONS.md](OPERATIONS.md).

Azure provisioning remains deferred by agreement. The remaining production design decisions are the identity-provider registration and roles, HTTPS ingress and public routing, independent-host availability, off-host backup retention and restore-time target, telemetry, and acceptance thresholds from independently labelled address inputs.
